# День 1 — Що таке Orca, перша сесія

**Сторінки доків:**
- https://www.onorca.dev/docs
- https://www.onorca.dev/docs/install

**Статус:** ✅ пройдено (2026-10-25)

## TL;DR
- Orca — desktop IDE, щоб запускати кілька AI-агентів паралельно. Кожна задача отримує **свій git worktree, свій термінал з агентом і свою вкладку браузера**.
- Orca — не модель і не заміна git: він запускає твої агенти (Claude Code, Codex, Cursor CLI…) з твоєю ж підпискою, а worktree там — звичайні git worktree.
- Базовий цикл: **Add Repo → «+» worktree → вибрати агента → повторити N разів з тим самим промптом → split panes → порівняти диффи → закомітити переможця, решту видалити**.

## Що розібрали

### Навіщо Orca
- Запустити кількох агентів на один баг паралельно й вибрати найкраще рішення.
- Уважно рев'юити AI-диффи перед шипінгом.
- Одне місце для оркестрації агентів, за які вже платиш.
- Запускати агентів віддалено (SSH, self-hosted Orca server, cloud VM), лишаючись в IDE.
- Розрахований на розробників, які читають диффи й дбають про коміти. Це не no-code інструмент.

### Чим Orca **не** є
- **Не модель** — підписку на Claude/Codex/OpenCode приносиш свою.
- **Не заміна git** — у будь-який worktree можна зайти через `cd` і працювати звичайним git.
- **Не хостинг/VPS** — за замовчуванням усе працює локально; для віддаленого запуску використовуються твої машини та твої хмарні акаунти.

### Встановлення та перший запуск
- macOS: `.dmg` (Apple Silicon / Intel) або `brew install --cask stablyai/orca/orca`; оновлення через `brew upgrade --cask orca` (тільки stable).
- Під час першого запуску Orca просить доступ до home-директорії, пропонує імпортувати `~/.claude`, `~/.codex` і налаштування Ghostty, а потім показує порожній екран, де додаєш перший репо.
- Автооновлення — канал **stable**. Більш ранні збірки ставляться через модифікатори на **Check for Updates**: **Shift+click** — RC, **Cmd+click** — perf-збірка, **Option+click** — локальна валідована збірка (лише macOS). Постійного перемикача на RC немає.
- Linux: CLI називається `orca-ide`, щоб не конфліктувати зі screen reader GNOME Orca.

### Перша сесія — ключові поняття
- **Base ref** — ref, від якого відгалужується кожен новий worktree. Береться з default-гілки репо, змінюється в налаштуваннях репо.
- **Start-from ref** — з чого стартувати конкретний worktree (зазвичай base ref, але можна будь-яку гілку чи коміт).
- **Ім'я worktree** — назва задачі. Якщо поле лишити порожнім, Orca назве worktree на честь морської істоти.
- **Launcher** — після створення worktree відкривається з **default agent** (Settings → Agents) або з порожнім терміналом.
- **Agent combobox** — вибір агента в терміналі. Orca запускає CLI агента в правильній директорії і передає йому твої облікові дані.
- **Pinned worktrees** — закріплені worktree, помітні в сайдбарі.
- **Split** — перетягни вкладку до правого або нижнього краю пейна.
- **Фініш** — diff view кожного worktree → Annotate AI Diff (коментарі назад агенту) → commit & push з Orca → решту worktree видаляєш одним кліком **разом із їхніми гілками**.

## Практика в Orca

Встановлений лише Claude Code, тому замість трьох різних агентів буде **2 worktree × Claude Code**. Сама ідея та сама: один промпт, порівнюємо два рішення.

1. **Add Repo** → вибери `~/Desktop/Courses/Orca/sandbox` (проєкт `sandbox`, окремо від `orca-learn`). Подивись, який **base ref** визначила Orca (очікуємо `main`).
2. Натисни **«+»** біля репо → назва `add-remove-todo` → start-from = base ref → агент **Claude Code**.
3. Ще раз **«+»** → **ім'я залиш порожнім** (подивись, яку морську істоту вибере Orca) → Claude Code.
4. В обидва агенти встав однаковий промпт:
   > Add a `removeTodo(todos, id)` function to `src/todo.ts` and a test for it in `src/todo.test.ts`. Make sure ids stay unique when you add a todo after removing one. Run `npm test`.
5. Розклади вкладки split'ом поруч і поспостерігай, як працюють обидва агенти.
6. Коли закінчать — відкрий diff view кожного. Порівняй: чи помітив агент, що `addTodo` рахує `id = todos.length + 1` (а після видалення це дає дублікати id)? Як він це виправив?
7. Поки **не коміть і не видаляй** worktree — вони знадобляться на День 2. Просто запиши, яке рішення краще і чому.
8. Перевірка в терміналі (з `~/Desktop/Courses/Orca/sandbox`): `git worktree list` і `git branch` — встав вивід мені.

## Результат практики
- Створив 2 worktree з Claude Code від `main` (`160f40c`): `add-remove-todo` і безіменний.
  - Безіменний отримав морське ім'я `loach`. Після першого промпта Orca перейменувала **гілку** на `remove-todo-unique-ids`, а папка лишилась `loach`.
  - Orca кладе worktree у `~/orca/workspaces/<проєкт>/<ім'я>`, а не поруч з репо.
  - У `git worktree list` був тимчасовий `.orca-preparing/... (detached HEAD) locked`. Схоже, це заготовка про запас (здогадка, в доках не знайшов), потім вона зникла.
- Обидва агенти спершу зупинились із планом і чекали «так». Причина — глобальне правило в `~/.claude/CLAUDE.md`. ✓ у сайдбарі означав «чекає на тебе», а не «готово».
- Обидва помітили баг `id = todos.length + 1` і виправили його на `max(id) + 1`. `src/todo.ts` в обох вийшов **ідентичний**, відрізняються лише тести. В обох `npm test`: 5/5.
- **Переможець:** `add-remove-todo`. Технічно рішення рівні, а цей агент відповідав українською, тож його легше читати.
- Split: за доками (`model/tabs-panes-splits`) кожен worktree має свою розкладку вкладок, тож split працює лише всередині одного worktree. Агентів з різних worktree порівнюєш через сайдбар.
- Перетягування worktree на інший worktree в сайдбарі робить його «child». На git це не впливає, це лише групування.
- Worktree не комітив і не видаляв, вони потрібні на День 2.
